# Willab — user stories and acceptance criteria

The canonical cross-stack user-story and acceptance-criteria set lives in the
backend repository, beside the product contract it derives from:

<https://github.com/wilplus/backend-cursor/blob/main/docs/USER_STORIES_AND_ACCEPTANCE_CRITERIA.md>

It covers all three perspectives — Speaker (end user), Coach, and Master Coach
(admin) — and maps every backend route **and every frontend page in this
repository** to the story that covers it (Appendix A and Appendix B there).

This file is intentionally a pointer rather than a duplicate, for the same
reason [`CANONICAL_PRODUCT_CONTRACT.md`](CANONICAL_PRODUCT_CONTRACT.md) is one:
two copies of a shared document cannot be kept honest, and a divergence between
them is itself drift.

Frontend runtime behavior, tests, terminology, and copy must conform to those
criteria, and to the contract above them. Where the two disagree, the contract
wins.
