What changes here

Settled

Every fork in this flow is now decided; the prototype is built to those calls.

  • One door per student, routed into judgement.
  • One queue per take — take 1, then take 2, then the feedback.
  • One delivery per arc — both takes go to the student together.
  • Exercises live in the CMS. A Yes or a No offers a link out that comes back to the same piece.
  • One action per screen, ending on Review and send.

Held fixed

No machine read, band or score reaches the judgement screen. The transcript stays hidden until that piece is answered. Pieces render in payload order — the queue is band-shuffled server-side so position is not a tell. An answer is required before the note field appears.
