# Test ↔ user story audit — 2026-10-19 (Linear WIL-78)

**Question:** do the existing tests actually test what their user stories say?
**Scope:** every automated test file in both repos. That is 571 files: 344 backend (`tests/test_*.py` plus `test_jwks.py`) and 227 frontend (`*.test.ts(x)`).
**Method:** each file was read by hand against its story. The story is what its name, docstring, `describe`/`it` text and comments promise. Each file got a written story in the form *As a … I want … so that … Outcome: …*: a user story when a speaker, coach or the founder feels the result, and a developer story only when no user ever does. Each file then got a verdict on whether its assertions prove that Outcome. The tests were read, not run: pytest/flask and the frontend `node_modules` are not installed in the audit container.
**Nothing in the code was changed.** This report only lists findings; fixing them is follow-up work.

## Verdicts

| | Proves its story | Only partly | Does not test its story | No user story | Files |
|---|---:|---:|---:|---:|---:|
| Backend | 96 | 179 | 50 | 19 | 344 |
| Frontend | 119 | 88 | 13 | 7 | 227 |
| **Both** | **215 (38%)** | **267 (47%)** | **63 (11%)** | **26 (5%)** | **571** |

- **Proves its story** (REALISES): the assertions check the promised outcome at a public seam (a route, a service contract, a DB contract, or what renders).
- **Only partly** (PARTIAL): it covers the story but misses a key outcome or asserts weakly.
- **Does not test its story** (MISMATCH): the test checks something else, or cannot fail when the story breaks.
- **No user story** (NO STORY): it tests a private helper, a library, style or plumbing.

The per-file tables below give every file its story, verdict, flags and the concrete fix.

## Suggested actions, in order
1. **Never-1:** close FE-1 (remove Hz/wpm/dB from speaker surfaces) and turn `f1LoopContract` AC-9 into a render test without `.fails`. Add one backend test per speaker readout route asserting that no score, rank, wpm, Hz or dB key is present. Delete `test_session_summary_allowlist.py`.
2. **Never-2:** replace the source-text greps with one route-level test per coach surface: create a moment with a machine value, read it as the coach before answering, and assert that the value is absent. Blind `kind` in `coachWalk.ts` until the moment is answered.
3. **Critical-path holes:** restore the positive cases listed in §4: Ideal Text paragraphs, practice-only erasure, the purge selector check, the real DB token charge, the paywall staying locked, and the balance refresh on success.
4. **Docstring honesty pass:** for every PARTIAL file flagged "docstring promises …", restore the key case or trim the story. Delete the files with no test functions, or give them their test.
5. **CI:** widen `rehearsal_trigger.sh` to the services the postgres tests drive.
6. **Founder answers needed:**
   - Is a progress percent allowed on the wait screen?
   - Should a zero token balance block the action or still work? The docstring and the assertion disagree.
