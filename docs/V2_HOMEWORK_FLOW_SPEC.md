# V2 Homework / Session Flow — Spec (Admin + Backend)

This document describes how the homework flow works from **admin panel** and **backend** perspectives.  
**Performance score formulas** (how `performance_score_1`, `performance_score_2`, `performance_score_end` are calculated) are **not** defined here — to be specified later.

---

## Flow overview

1. **Task warm-up + recording_1** → 3 metrics → `performance_score_1`
2. **AI-generated task text** (context_short + focus_task + metric_question_1 + metric_question_2)
3. **Final task + recording_2** → 5 metrics → `performance_score_2`
4. **Questions** (optional; admin-configurable)
5. **Report** (context_short + performance_score_end + question answers) → stored as `context_long`; report sent to admin history
6. **Admin** can update parameters and re-send homework to the student

---

## Step 1: Task warm-up → recording_1 → 3 metrics

**User experience:**  
The user first sees **one** **task_warm_up** text, then records **recording_1**. That recording is measured on **3 metrics**: strength, fillers, pacing.

| Perspective | Details |
|-------------|---------|
| **Admin panel** | **task_warm_up** is a **list** (per student). Admin can **edit**, **update**, and **delete** task_warm_up items. (Exact UI: list on the student profile or a dedicated “Task warm-up” section.) |
| **Backend** | **performance_score_1** is calculated from the 3 metrics (strength, fillers, pacing) on a scale **0 to 1** (0% to 100%). *Calculation formula TBD.* |

---

## Step 2: AI-generated task text (after recording_1)

**User experience:**  
After recording_1, the user is shown a **task text** generated by the AI with this structure:

- **context_short** — extracted by AI from recording_1  
- **focus_task** — from admin list (which one is chosen depends on performance_score_1)  
- **metric_question_1** — from admin Metrics  
- **metric_question_2** — from admin Metrics  

| Perspective | Details |
|-------------|---------|
| **Admin panel** | • **Context**: Extracted by AI from recording_1 (not directly editable; comes from backend).<br>• **focus_task**: A **list** (per student). Admin can **edit**, **update**, **delete** focus_task items. Each focus_task has **Min Task Score** and **Max Task Score** (0–1) — the score range for which the task is available.<br>• **metric_question_1** and **metric_question_2**: **Two fixed questions** in the admin **Metrics** section. Admin can **edit**, **delete**, **add** (the two slots). |
| **Backend** | **performance_score_1** is used to choose which **focus_task** is shown. Each focus_task has Min Task Score and Max Task Score (0–1). A focus_task is **eligible** when **min_task_score ≤ performance_score_1** (or “min score” ≥ threshold, depending on product rule) are eligible. E.g. if performance_score_1 = 0.1, only tasks with min 0.1 or lower (0.05, 0.1) are eligible; min 0.2 is not. If **more than one** focus_task is eligible, the backend picks one via **random.shuffle()** (or equivalent). |

---

## Step 3: Final task → recording_2 → 5 metrics

**User experience:**  
The **final_task** text is generated by the AI with structure:

- **context** (from recording_1)  
- **focus_task** (the one chosen in step 2)  
- **metric_answer_1** (student’s answer to metric_question_1)  
- **metric_answer_2** (student’s answer to metric_question_2)  

The user sees this **final_task** text, then records **recording_2**. Recording_2 is measured on **5 metrics**: strength, fillers, pacing, metric_answer_1, metric_answer_2.

| Perspective | Details |
|-------------|---------|
| **Admin panel** | At this step there are **no variables** directly controllable by the admin. |
| **Backend** | **performance_score_2** is calculated from the 5 metrics on a scale **0 to 1** (0% to 100%). *Calculation formula TBD.* |

---

## Step 4: Questions

**User experience:**  
After the user finishes recording_2, they are shown **questions** to answer.

| Perspective | Details |
|-------------|---------|
| **Admin panel** | Admin **chooses which questions** the user answers. Admin can **delete**, **edit**, and **add** questions. If **no questions** are configured, this step is **skipped**. |
| **Backend** | Question answers are saved to a variable (e.g. **questions** or equivalent structure) and used later in the report. |

---

## Step 5: Report

**User experience:**  
The user is shown a **report** that includes:

- **context_short**  
- **performance_score_end** = (performance_score_1 + performance_score_2) / 2  
- **Answers to the questions** (from step 4)  

The report is **delivered by AI** (generated using the above inputs).

| Perspective | Details |
|-------------|---------|
| **Admin panel** | Admin can **delete**, **edit**, **overwrite** the report. The (final) report is **appended** to **context_long** (see backend). |
| **Backend** | The end report is **generated by AI** from: context_short, performance_score_end, and the question answers. Report is **appended to context_long with a timestamp** so there is a full history of observations; if context_long gets too long, it can be summarized later with AI. *Performance score calculation formulas TBD.* |

---

## Step 6: After report — history and re-send

**User experience:**  
The user finishes the homework. The report is sent to the admin and stored in the **history** tab. **context_long** is updated by **appending** the report **with a timestamp** (full history; can be summarized with AI later if too long).

| Perspective | Details |
|-------------|---------|
| **Admin panel** | Admin sees the report in **history**. Admin can **update** the above-mentioned parameters (task_warm_up list, focus_task list, metric questions, questions pool, etc.) and **re-send the homework** to the student. |
| **Backend** | Report and context_long are persisted; history is available to the admin. Re-send uses current overrides and lists. |

---

## Summary table (admin-editable vs backend-calculated)

| Step              | Admin-editable / Admin-controlled                    | Backend-calculated / Backend logic                         |
|------------------|------------------------------------------------------|------------------------------------------------------------|
| 1. Warm-up       | task_warm_up list; admin chooses which one is shown (student sees 1) | performance_score_1 from 3 metrics (formula TBD)           |
| 2. Task text     | focus_task list (Min/Max Task Score), metric_question_1/2 (Metrics, two fixed) | context_short (AI from recording_1); focus_task eligible when min_task_score ≤ performance_score_1; random if >1 |
| 3. Final + rec_2 | —                                                    | performance_score_2 from 5 metrics (formula TBD)          |
| 4. Questions     | Which questions; add / edit / delete; skip if none   | Save answers to `questions`                               |
| 5. Report        | Delete / edit / overwrite report; report appended to context_long | Generate report (AI); append to context_long with timestamp |
| 6. History       | View report; update params; re-send homework         | Persist context_long; serve history                       |
